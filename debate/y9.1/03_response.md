# 03. Codex 비판에 대한 응답 — Claude

| 지적 | 응답 | 반영 |
|---|---|---|
| C1 [치명] 회전 후에는 die 경계를 못 맞춤 | 수용 | 노이즈는 **회전 전** 원본 die 단위로 추첨: 배치 인덱스로 (h, w) 를 찾고, die 마다 난수 하나 → 그 die 의 모든 캐시 픽셀을 1→2. 그 뒤 뷰마다 독립 회전. 96 초과 격자 (사전학습 10만 장 중 약 5.3%) 는 캐시 픽셀을 원본 die 좌표로 묶음. 검사: p=0 이면 입력 그대로, p=1 이면 정상 die 전부 불량, 배경·기존 불량 보존 |
| C2 진단 경로에 test | 수용 | probe 학습은 라벨 6,919장, 채점·선 민감도·합성선 진단은 모두 **val**. test 는 설정 확정 후 보고만 |
| C3 seed 0 + macro 단독 기준 부족 | 수용 | 진행 기준을 미리 고정 (아래). 보고: seed 별 y9 대비 val macro 차, 소수 5개 F1 차, Scratch 재현율, Scratch→none/Loc 건수. test 에서 macro 0.795 와 소수 하한 모두 확인 |
| C4 근거 해석 과장 | 수용 | (1) 0.078 vs 0.107 은 선 픽셀까지 포함한 전체 불량 비율이라 "배경 밀도" 로 단정 못 함. (2) 조작 실험에서 배경을 지우면 Scratch 가 오히려 떨어졌으니 "배경 잡음 때문" 은 일부만 맞음. (3) 마스킹 검증의 0.61 은 "비율이 같다" 는 뜻이지 민감도 크기가 같다는 뜻이 아님 (특징 변화량 SimCLR 0.0655 vs ver8 0.0042). → 가설을 **"같은 선을 고정하고 흩어진 불량을 늘릴 때, y9.1 의 Scratch 판정이 y9 보다 덜 흔들리는가"** 로 좁힘 |
| C5 네 강도 혼합의 해석 한계 | 수용 | 혼합 설정의 결론은 그 설정에 한정. 손실은 y9 와 동일, 뷰별 cosine 을 기록. 강도 자체의 비교는 별도 실행 (파일럿에서 약한 고정 p 와 혼합 비교) |
| C6 붕괴 판정 기준 | 수용 | 같은 epoch 의 y9 z_std 추이와 비교 + 고정 val 표본 특징의 유효 랭크 + probe. 여러 지표가 함께 나빠질 때만 조기 중단. 제안서의 "12 스텝 0.06" 은 로그로 확인되지 않아 삭제 |
| 빠진 대조군: 회전만 (p=0) | 수용 | 파일럿에 포함 → "마스킹을 뺀 효과" 와 "불량을 더한 효과" 분리 |
| 실행 조건 일치 | 수용 | 같은 10만 장·라벨 6,919장·v3_nopl·SSL 50·FT 3×30, 별도 인코더 파일명·결과 태그, 기존 done 때문에 건너뛰지 않는지 확인 |
| 대안: 기존 y9 로 먼저 점검, 동일 예산 파일럿 | 수용 | 0단계와 1단계로 반영. 시간 추정도 수정 (y9 의 SSL 만 seed 0 4.1시간, seed 1 6.5시간) |

## 수정한 계획
0. **(GPU 수 분, 학습 없음)** 기존 y9 seed 0 모델로 val 웨이퍼에 같은 합성선을 그리고 흩어진 불량을 0→16% 단계적으로 추가 (die 수·선 두께 고정). Scratch 점수와 none/Loc 전이 곡선. → y9 가 이미 잡음에 강하면 y9.1 의 동기가 약해짐 (그 경우 사용자와 재논의).
1. **파일럿 (seed 0, 같은 예산, SSL 10 epoch 씩)**: ① 6px 마스킹 (y9 와 같음) ② 회전만 (p=0) ③ 노이즈 혼합 p=2/4/8/16% ④ 노이즈 고정 p=4%. 각 인코더로 val probe (kNN·선형) + 0단계와 같은 잡음 곡선 + z_std·유효 랭크. 4 조건 × 약 50분 ≈ 3.5시간.
2. **본 실험**: 파일럿에서 val probe 와 잡음 곡선이 가장 좋은 노이즈 설정 하나를 50 epoch 사전학습 + fine-tune (seed 0, 약 5시간). 진행 기준: y9 seed 0 대비 val macro 가 높고, 소수 5개 클래스 val F1 중 0.03 넘게 떨어진 것이 없을 것.
3. 2를 통과하면 seed 1 반복 (약 7시간).
코드 변경 (1단계 전에): augment.py 에 die 단위 랜덤 불량 함수, ver6.py `_views` 에 노이즈·회전만 모드와 뷰별 cosine 기록, wafixmatch.py 에 파일럿·본 실험 이름 등록 (약 60줄). 0단계는 분석 스크립트만.

## 추가 발견 (응답 작성 후, SimCLR 비교 중)
- 우리 SimCLR (ver3) 의 증강에 **이미 노이즈가 들어 있다**: `augment.py:83` `noise()` = 웨이퍼 안 픽셀을 5% 확률로 정상↔불량 **양방향** 뒤집기, 픽셀 단위.
  SimCLR 뷰는 회전 후 {crop, cutout, noise, rotate, shift} 중 2개를 무작위 적용 (`selfsup.py:57`, `augment.py:22`) → 한 뷰에 noise 가 들어갈 확률 약 40%.
- 따라서 y9.1 은 "ver7 목적함수 + SimCLR 에 있던 노이즈를 die 단위·불량 추가 방향으로 바꾼 것" 이다. SimCLR 의 Scratch 우위 (0.616) 가 노이즈 때문인지, 음성 쌍 (밀어내기)·projector 때문인지는 아직 분리되지 않았다.
- 파일럿에 **기존 ver3 SimCLR seed 0 인코더** 를 참고선으로 함께 평가한다 (추가 학습 없음).
