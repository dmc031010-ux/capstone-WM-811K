# 07. 최종 정리 — Claude (2026-11-23)

Codex 결과 검토 (06) 의 지적을 모두 수용하고 05 를 아래처럼 고친다.

## 고친 결론
- **R1 test 노출**: 체크포인트는 val macro 로 골랐지만, 기존 파이프라인 (`engine.py _Tracker`) 이 val 최고점마다 test 도 평가해 로그·metrics.json 에 남긴다. 05 의 "test 는 보지 않음" 은 "분석에서 test 를 읽지 않음" 으로 좁힌다. 이전 버전도 같은 방식이었다. 후속 실행에서 test 평가를 끌지 여부는 사용자 결정 사항.
- **R2 클래스별 하락**: 소수 5 평균에 가려져 있었다. y9 (50ep) 대비 ③ Donut −0.060, Near-full −0.043, ④ Loc −0.035 → **두 후보 모두 10 epoch 시점에선 진행 기준 미달.** 또 cosine 학습률이 총 epoch 에 맞춰 감쇠하므로 10 epoch 결과를 50 epoch 의 중간값으로 읽을 수 없다.
- **R3 잡음 곡선**: 8% 에서 ④ 22/114 vs ③ 18/114 는 4장 차이. "④ 가 잡음에 가장 강하다" 는 주장은 철회. 합성선·die 수 구간·none 오탐·16% 가 빠졌다.
- **R4 선형 probe**: "이 seed 에서 ④ 의 선형 probe 가 높았다" 까지만. FT 후 val Scratch 119장 기준 ③→④ 정분류 60→49, none 오분류 39→60 → **FT 후엔 ④ 가 Scratch 를 none 으로 더 많이 보냄.**
- **R5 projector**: ② 는 projector 추가와 함께 출력 차원이 512→128 로 바뀌어 "projector 효과" 가 아니라 "헤드 구성 변경 효과". z_std 도 차원이 달라 ① 과 직접 비교 불가.
- **R6 뷰별 cos 역전**: 로그상 학습 중 바뀌는 현상 (epoch 1 은 8%>16%, epoch 10 은 역전). 원인 미확인.
- **R7 속도**: epoch 2~10 평균 475~482초 관측. 원인이 전력 제한이라는 것은 nvidia-smi 관측에 근거한 추정이고, 점수 영향 없음은 검증하지 않음.

## 말할 수 있는 것
seed 0 · SSL 10 epoch · 같은 FT 예산에서 ③ (회전만 + proj) 이 FT val macro (0.815) 와 Scratch F1 (0.524) 이 가장 높았고, ④ (노이즈 + proj) 는 고정 인코더 선형 probe (0.677) 가 가장 높았다. 어느 조건도 y9 50ep (0.818) 를 넘지 못했고, 클래스별 기준도 통과하지 못했다.

## 추가: 노이즈 진단 보강 결과 (`runs/y9.1_noise_diag/`, val, 학습 없음)
6개 모델 × 노이즈 5세트 × 0~16%, 같은 웨이퍼 짝비교 (웨이퍼 부트스트랩 95% 구간). 노이즈 세트 간 표준편차는 0.00~0.03 으로 작음.
- **③ 회전만이 가장 강건**: 실제 Scratch 에서 y9 대비 0~8% 전 구간 +0.09~+0.15 (구간이 0 을 안 넘음). die 많은 합성선 8% 에서 0.59 vs y9 0.14.
- **④ 노이즈는 ③ 보다 나은 구간이 없음** (16% 만 +0.04, 둘 다 0 근처). 8% 실제 Scratch 에서 ④ − ③ = +0.002 → 파일럿의 "④ 가 8% 에서 최고" 는 차이 없음으로 확정.
- **④ 의 부작용**: die 적은 합성선에서 ③ 대비 −0.25 (0% 에서도). 판정이 none 으로 감 (0.58). 노이즈 사전학습이 "die 적은 웨이퍼의 드문드문한 불량 = 잡음" 으로 배운 것으로 보임 → 우리 약점 그룹을 더 나쁘게 함.
- ④ 는 마스킹 (①·y9) 대비로는 4~8% 에서 강건해짐 (실제 Scratch 8%: +0.12~+0.15).
- none 오탐: 모든 모델 ≤ 0.003. 16% 에서 none 유지 ① 0.88, ④ 0.99.
- 한계: 부트스트랩은 웨이퍼 표본 오차만 반영. 학습 seed 차이는 반영 안 됨 (모두 seed 0 체크포인트 1개). ③·④ 는 10ep, y9 는 50ep.

## 추가: 레이어별 probe (`runs/y9.1_layer_probe/`, val 5-fold×3, 학습 없음)
fine-tune 된 seed 0 모델 4개, Scratch vs none / Scratch vs Loc AUC.
- 정보는 레이어를 지날수록 **늘어남** (vs none stem 0.84 → layer3 0.97~0.98). 초반에 사라지는 증거 없음.
- layer4 에서 약간 감소 (−0.01~−0.03). Max vs Avg 차는 layer4 에서 +0.00~+0.01 → AvgPool 희석은 작음.
- die 적은 웨이퍼는 stem 에서 크게 낮지만 (0.74 vs 0.94) layer3~4 에서 거의 따라잡음 (③ 0.959 vs 0.968).
- **가장 큰 손실은 layer4 특징 → 모델 자신의 최종 출력 (fc)**: vs Loc ① 0.925→0.874, ③ 0.961→0.901, y9 0.933→0.872. ③ 의 vs none 에서 die 적음 0.959→0.922 로 die 격차가 다시 생김. SimCLR 은 vs none 에서 예외 (0.961→0.985).
- 주의: probe 는 val 라벨 (Scratch 119장) 로 학습, fc 는 train Scratch 약 48장. 차이는 "특징 안에 정보는 있는데, 적은 라벨로 학습한 판정층이 다 못 씀" 으로 읽어야 함 (probe = 상한).
