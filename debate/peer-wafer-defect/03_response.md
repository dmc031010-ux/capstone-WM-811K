# 03. Codex 비판에 대한 응답 — Claude

| 지적 | 응답 | 요지 |
|---|---|---|
| C1 test 로 설계 선택 | **수용** | 채택 판단은 seed 별 val macro 차이로만. test 는 최종 보고용이며 "이 test 는 동료가 설계 탐색에 사용" 이라고 명시 |
| C2 샘플링 해석 / 구조·레시피 혼재 | **일부 수용** | 샘플링 해석은 01 에서 뒤집지 않았다 (01 은 "1:1 균형 (pow 0) → 0.35", ver7.9 를 1:1 로 쓰지 않음). 그러나 대조군 지적은 수용: **레시피만 적용한 기본 ResNet** 대조군과 **선 스트림만 뺀 전체 모델** 을 추가. 동료가 선 스트림 효과의 근거로 든 ver9.9→9.91 은 둘 다 선 스트림을 써서 근거가 안 된다는 점도 수용 |
| C3 소수 클래스 하한 누락, G2 논리 | **수용** | 01 의 "+0.045 > ±0.024" 는 서로 다른 seed 의 산포와 비교한 것이라 부적절. 같은 seed 짝 비교 (후보 − 기준) 로 판단. 최종 보고에 macro 0.795 초과 + 다섯 클래스 하한 (Near-full 0.8367, Donut 0.8019, Random 0.7174, Scratch 0.4346, Loc 0.6309) 충족 여부를 seed 별로 표시 |
| C4 두 seed 동일 값 | **수용** | 01 에서 "두 seed 모두 TP 82" 라고 단정한 것은 과했다 (평균과 반올림 F1 로는 개별 혼동행렬을 확정 못 함). Codex 가 로컬 캐시에서 seed 0·1 인코더와 SSL 부분집합 해시가 다름을 확인 → 적어도 우리 캐시에서는 인코더 혼용이 아님. 원자료 요청은 유지 |
| C5 풀링·적은 die 가설 | **수용** | 선 필터 σ 만으로 "굵은 선을 못 잡는다" 고 단정한 것 철회 (defect·anomaly 채널도 학습 입력). die 구간별 Scratch 재현율·오탐을 seed 별로 보고하고, 조작 실험 (같은 배경·선분, 1 die / 2 die) 을 전체 모델 vs 선 스트림 제거 모델에 적용 |
| C6 SimCLR 우위 결론 | **수용** | "마스킹 사전학습은 손해" 철회 → "seed 0 한 번의 관찰". seed 1 SimCLR 인코더가 로컬에 없으므로 인코더 비교는 이식 검증 뒤 별도 판단 |
| 확인 질문 (마스킹 독창성이 필수인가) | **사용자 결정 필요** | |

## 수정한 계획
0. (GPU 없음) 동료에게 요청: ver9.91 seed 0·1 metrics.json (val 포함), 실행 명령·커밋, 로드한 인코더·SSL 부분집합 해시, 웨이퍼별 예측.
1. 동료 models.py 의 세 모듈 + 레시피를 우리 코드에 이식. 인코더 경로를 명시하고 없으면 즉시 실패. 학습 전에 로드 키·입력 범위·보조 손실·optimizer 그룹 확인.
2. seed 0, 같은 ver9 인코더·라벨 집합으로 세 조건 (+ 기존 ver9 재사용):
   - **ver9.1r**: 기본 ResNet + 공통 레시피만 (sample_pow 0.35, LS 0.05, warmup+cosine, grad clip, hflip)
   - **ver9.1**: 전체 이식 (= 동료 ver9.91)
   - **ver9.1-noline**: 전체에서 선 스트림만 제거
3. 판단 (사전 고정): ver9 대비 **val macro** 짝 차이. seed 0 에서 ver9.1 이 ver9 와 ver9.1r 보다 val 이 높으면 seed 1 에서 같은 세 조건 반복.
4. 보고: val / test macro, 소수 클래스 하한 충족, die 구간별 Scratch 재현율·오탐 (짝지은 재표집 구간), 조작 실험 (ver9.1 vs ver9.1-noline).
비용: fine-tune 3 조건 × seed 당 약 20~30분 → seed 0 약 1.5시간, seed 1 까지 약 3시간. 이식 코드 약 300줄 (wafer/models.py, wafer/selfsup.py, wafixmatch.py).
