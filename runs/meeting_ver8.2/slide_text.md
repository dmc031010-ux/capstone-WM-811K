# ver8.2 · FiLM으로 웨이퍼 크기 정보를 인코더 중간에 넣기

## 동기
- die 수가 적은 웨이퍼에서 Scratch를 많이 놓침 (test 재현율: die < 1200 31%, die ≥ 1200 63%, ver8 seed 0).
- ver8.1은 크기 정보를 분류기 직전에만 붙임. 이 방식은 클래스 점수에 크기별 보정값을 더할 뿐이고, 그림 특징 자체는 바뀌지 않음.
- 그래서 ver8.2는 크기 정보로 **특징을 뽑는 방식 자체**를 조절하도록 설계함.

## 방법 (그림 1)
- 크기 s = 표준화한 log(die 수).
- FiLM Generator(Linear 1→16, ReLU)가 ResNet의 4개 stage마다 채널별 γ, β를 생성함.
- 각 stage 출력 h를 h × (1 + γ) + β로 바꿈.
- γ, β를 만드는 층은 0으로 초기화. 학습을 시작할 때는 일반 ResNet과 똑같음.
- 사전학습(온라인·타깃 인코더 모두)부터 크기를 넣음. 나머지 조건은 ver8과 같음.
- 실험 규모: seed 0, 1. seed당 사전학습 약 3.6시간.

## 결과 (그림 2~4, test 17,296장, seed 0 / seed 1)

| | ver8 | ver8.1 | ver8.2 |
|---|---|---|---|
| test macro F1 | 0.831 / 0.783 (평균 0.807) | 0.822 / 0.829 (0.826) | 0.803 / 0.813 (0.808) |
| val macro F1 | 0.818 / 0.795 (0.806) | 0.814 / 0.807 (0.811) | 0.786 / 0.791 (0.788) |
| Scratch F1 | 0.477 / 0.444 (0.460) | 0.441 / 0.520 (0.481) | 0.367 / 0.438 (0.402) |
| 사전학습 후 NMI | 0.111 / 0.079 | (ver8과 같은 인코더) | 0.137 / 0.152 |

- 성능은 ver8과 평균이 같음(0.808 vs 0.807). val은 세 방법 중 가장 낮음.
- Scratch는 오히려 떨어짐(평균 0.460 → 0.402).
- die 수 적은 웨이퍼의 Scratch 맞힘은 seed 0 12/61, seed 1 25/61로 방향이 일정하지 않음.
- 사전학습 특징의 클래스 군집 정도(NMI)는 두 seed 모두 좋아짐. 하지만 fine-tune 성능으로 이어지지 않음.
- 사전학습 손실은 정상적으로 줄었고, 붕괴는 없었음(그림 5).

## 해석
- 크기 정보를 앞에 넣든(FiLM) 뒤에 넣든(ver8.1), die 수가 적은 웨이퍼의 Scratch 문제는 해결되지 않음.
- 후속 검증(조작 실험)으로 원인을 확인함.
  - 같은 1 die 폭 선을 넣어도 die가 크면 96×96 입력에서 약 3.5픽셀 굵기가 됨.
  - 모델은 굵은 선을 Scratch로 보지 않음. die 많은 웨이퍼에 2 die 폭 선을 넣으면 Scratch 판정이 0.90에서 0.11로 떨어짐.
  - 즉 필요한 것은 "크기를 알려주는 것"이 아니라 "**픽셀 굵기와 상관없이 선을 알아보게 하는 것**".

## 다음 단계 제안
- die 크기 증강: die 격자를 무작위로 합치거나 쪼개서, 같은 Scratch를 여러 굵기로 학습함. fine-tune만으로 가능.
